# Jellibi Robot Contest | 2026

**국제로봇콘테스트 물류이송 로봇(AGV) 주행·팔레트 운반 프로젝트**

Arduino Nano 기반 Jellibi 로봇으로 격자형 경기장의 검은 라인을 따라 이동하고, 교차점과 장애물을 인식해 지정된 경로를 주행하도록 구현한 대회용 코드입니다. 종목 1의 고정 경로 주행, 종목 2의 장애물 회피·팔레트 상하차, 모터·리프트 보정용 스케치를 정리했습니다.

이 저장소는 **대회 당시 주행 로직과 제어 상수를 보존한 공개용 아카이브**입니다. 공개본에서는 실제 RFID 카드 UID를 제거하고 시작 기능을 기본 비활성화했습니다. 코드는 특정 로봇과 경기장 조건에 맞춰 조정되었으며, 다른 기체에서의 동작이나 전체 미션 완주를 보장하지 않습니다.

## 핵심 구현

| 기능 | 구현 방식 | 
| --- | --- |
| 라인트레이싱 | 2개의 바닥 IR 센서 차이를 이용한 PD 조향 보정 |
| 교차점 주행 | IR 기반 교차점 감지와 격자 노드 단위 경로 실행 |
| 방향 전환 | 좌·우 모터 역방향 구동과 시간 기반 90°/180° 회전 |
| 적재 상태 대응 | 빈 차/적재 상태의 속도·PD·회전 파라미터 분리 |
| 장애물 탐색 | 전방 센서 측정으로 통과 가능한 열 선택 |
| 팔레트 운반 | 리프트 서보를 이용한 상차·하차 순서 제어 |
| 현장 보정 | 직진 PWM, 회전 PWM·시간, 리프트 구동을 시리얼 명령으로 시험 |

> **구현 범위:** 카메라/SLAM 기반 자율주행이 아닌, 사전에 정의된 격자 지도와 바닥 IR 센서·전방 센서를 사용하는 경로 주행 방식입니다. 회전량은 각도 센서의 피드백 없이 시간으로 제어합니다.

## 종목별 동작

### Mission 1 — 고정 경로 주행

- **시작:** 외부 T2 지점에서 H2 방향으로 배치, RFID 카드 인식 후 출발
- **주행:** 지정된 교차점 순서대로 직진·좌회전·우회전·유턴 수행
- **종료:** H6 아래 외부 T6 지점 검출 즉시 모터 정지, 2.3초 대기
- **정지 입력:** A3 버튼(LOW)으로 주행 중단

### Mission 2 — 장애물 탐색 및 팔레트 운반

- **시작:** 외부 T5에서 H5 방향으로 배치, RFID 카드 인식 후 출발
- **1차 운반:** D1~D3 통로 탐색 → A6 외부 상차 → H2 외부 하역
- **2차 운반:** D7/D8 통로 탐색 → A4 외부 상차 → H6 외부 하역 후 정지
- **장애물 조건:** D4~D6 고정 장애물, D1~D3 중 1개, D7/D8 중 정확히 1개

종목 2의 D7/D8 판단은 **정확히 한 곳이 막혀 있다는 경기 조건**을 이용합니다. D7이 막히면 D8을 추가 측정하지 않고 통과 가능한 것으로 간주합니다. 따라서 장애물 배치가 달라지는 일반 환경에는 그대로 적용할 수 없습니다.

※ `A6`, `A4` 등은 **경기장 좌표**입니다. 아두이노의 아날로그 핀 `A6`와는 별개입니다.

## 하드웨어 및 개발 환경

- **보드:** Arduino Nano 계열(바닥 IR 센서용 A6/A7 아날로그 입력 필요)
- **주행:** DC 모터 2개, 바닥 IR 센서 2개
- **종목 2 추가:** 전방 장애물 센서, 리프트 서보
- **출발:** RFID 리더기, 부저
- **개발:** Arduino IDE / Arduino C++
- **라이브러리:** `SPI`, `MFRC522`(종목 1·2), `Servo`(종목 2·Calibration)

| 기능 | Arduino 핀 |
| --- | --- |
| 좌/우 모터 PWM | D5 / D6 |
| 좌/우 모터 방향 | D7 / D8 |
| 좌/우 바닥 IR | A6 / A7 |
| RFID SS / RST | D2 / D4 |
| 부저 | D3 |
| 종목 1 정지 버튼 | A3 (`INPUT_PULLUP`, LOW 입력) |
| 종목 2 전방 센서 | A0 |
| 리프트 서보 | D9 |

핀 표는 스케치에 설정된 **신호 핀**만 나타냅니다. 전원·접지·모터 드라이버·RFID SPI 배선은 실제 기체와 별도로 확인해야 합니다.

## 실행 방법

1. Arduino IDE에서 사용할 스케치의 `.ino` 파일을 엽니다. 예: `Mission1/Mission1.ino`.
2. 보드·프로세서/부트로더·포트를 실제 기체에 맞춰 선택하고 필요한 라이브러리를 설치합니다.
3. 종목 1·2는 아래 설명에 따라 **로컬에서만 RFID UID를 설정**합니다.
4. **Verify(컴파일)** 후 **Upload**합니다. 시리얼 모니터는 **9600 baud**로 설정합니다.
5. 로봇을 해당 종목의 출발 위치와 방향에 배치한 뒤 RFID 카드를 인식시킵니다.

종목 1·2는 종료 또는 실패 후 **리셋해야 재시작**합니다. 종목 1의 A3 입력은 소프트웨어 주행 중단이며 별도 전원 차단형 비상정지 장치가 아닙니다. 종목 2에는 동일한 A3 정지 입력이 없습니다.

### RFID 카드 설정(공개본)

공개본에는 UID 자리표시자가 들어 있으며 `RFID_UID_CONFIGURED = false`입니다. 이를 그대로 업로드하면 RFID로 출발하지 않습니다.

1. `Mission1.ino`의 `allowedUid`, `Mission2.ino`의 `uid` 배열에 **본인 카드의 4바이트 UID**를 입력합니다.
2. 사용할 스케치의 `RFID_UID_CONFIGURED` 값을 `true`로 바꿉니다.
3. 보드에 다시 업로드하되, **실제 UID가 포함된 로컬 수정본을 공개 저장소에 커밋하지 않습니다.**

UID 일치 검사는 대회용 출발 조건일 뿐, 복제에 강한 보안 인증 방식은 아닙니다.

## Calibration — 모터·리프트 보정

`Mission2Calibration.ino`는 **라인 추종·RFID·자동 경로 주행 없이** 모터와 리프트를 개별 시험하는 스케치입니다.

시리얼 모니터를 `9600 baud`, 줄 끝을 `Newline` 또는 `Both NL & CR`로 설정합니다.

| 명령 | 기능 |
| --- | --- |
| `e` / `b` | 빈 차(리프트 55°) / 적재(리프트 170°) 프로필 선택 |
| `f` | 직진 시험 |
| `a` / `d` / `u` | 좌회전 / 우회전 / 유턴 시험 |
| `L 120` / `R 120` | 현재 프로필의 좌/우 모터 PWM 설정 |
| `T 1000` | 직진 구동 시간(ms) 설정 |
| `P 100` | 회전 PWM 설정 |
| `A 460` / `D 460` / `U 900` | 좌회전 / 우회전 / 유턴 시간(ms) 설정 |
| `s` 또는 `S` | 동작 중 모터 정지 및 진행 중인 서보 이동 중단 |
| `?` / `h` | 설정 출력 / 도움말 |

**사용 순서:** `e` 또는 `b` 선택 → `READY` 확인 → 구동 명령 실행 → 실제 이동 거리·회전각 측정 → 파라미터 조정 → `?`로 결과 기록.

설정은 **RAM에만 저장**되어 리셋 시 초기화되고, 종목 1·2 스케치에 자동 반영되지 않습니다. 특히 Calibration은 좌우 PWM을 직접 설정하지만 미션 스케치에서는 왼쪽 모터에 출력 비율을 적용하므로, 값을 그대로 복사하면 같은 주행을 보장하지 않습니다.

## 코드에 남아 있는 주요 보정값

| 항목 | Mission 1 | Mission 2 빈 차 | Mission 2 적재 |
| --- | ---: | ---: | ---: |
| 기본 순항 PWM | 207 | 170 | 100 |
| 접근 PWM | 145 | 125 | 90 |
| 복구 PWM | 140 | 100 | 100 |
| 좌회전 시간(ms) | 350 | 340 | 455 |
| 우회전 시간(ms) | 360 | 350 | 455 |
| 유턴 시간(ms) | 690 | 660 | 890 |

위 값은 **해당 스케치에 정의된 값**이며 모든 기체에서 검증된 최적값을 의미하지 않습니다. Calibration의 기본값(빈 차 L120/R120, 적재 L100/R100)은 별도 초기 시험값입니다.

## 개발 과정에서 다룬 문제

| 관찰한 문제 | 코드에 반영한 대응 | 남아 있는 한계 |
| --- | --- | --- |
| 좌우 모터 출력 차이로 직진 경로가 한쪽으로 쏠림 | 좌우 PWM과 왼쪽 출력 비율을 별도로 보정 | 배터리 전압·하중이 바뀌면 재보정 필요 |
| 팔레트 적재 후 조향 및 회전 특성이 달라짐 | 빈 차/적재 상태에 별도 순항 속도, PD 게인, 회전 시간을 적용 | 모든 하중 조건에서의 안정성을 검증한 것은 아님 |
| 회전 직후 라인 재진입이 불안정함 | 정렬·안정화 대기 및 적재 상태 미세 보정 로직을 적용 | 회전각을 직접 측정하지 않아 오차가 남을 수 있음 |
| 교차점 중복 인식 또는 검출 실패 | 교차점 감지 조건과 재인식 간격을 설정 | 바닥 상태와 센서 위치에 민감함 |

위 표는 **실험 중 관찰한 문제와 코드에 반영한 대응**을 정리한 것으로, 정량적인 개선율이나 모든 코스 완주를 증명하는 자료는 아닙니다.

## 검증 범위 및 알려진 한계

- 사용한 모터와 배터리 상태, 바닥 반사율, 팔레트 하중에 따라 IR 값과 회전량이 달라질 수 있습니다.
- 회전은 시간 기반이므로 실제 각도에 편차가 생길 수 있고, 적재 후 선 이탈이나 교차점 검출 실패 가능성이 있습니다.
- 종목 2의 장애물 탐색은 경기장에 주어진 배치 규칙에 의존합니다.
- 코드에 남아 있는 `HOST_SIM`, `M2_ROUTE_TEST`는 별도 시험용 조건부 코드입니다. 관련 외부 시뮬레이터와 시험 보고서는 이 저장소에 포함하지 않았습니다.
- 공개용 UID 제거 이외의 변경 사항과 확인 가능한 검증 범위는 `docs/SOURCE_VERIFICATION.md`, `docs/PUBLICATION_REVIEW.md`를 참고하세요. **실제 완주 성공 여부나 컴파일·실기 검증 결과는 확인된 기록이 있을 때만 추가합니다.**
